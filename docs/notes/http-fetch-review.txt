HTML 抽出で `a[href]` が失われ anchor text だけ残る (引用不能・next-hop 不能) **実測 (同一 page の HTML と .md を比較)** [1] | 項目 | HTML (`.../quick-start/`) | Markdown (`.../quick-start.md`) | |---|---|---| | `query="docs.docker.com"` | **一致なし** [1] | 多数ヒット | | `query="](https://"` | **一致なし** [1] | 多数ヒット | | `[full update guide](/getting-started/updating)` | 「see the full update guide **.**」→ URL 消失 [1] | 相対リンク保持 | | 取得/本文 | 215.4k bytes → 50.5k字 ≈13.1k tok [1] | 57.9k bytes → 55.9k字 ≈14.5k tok | **原因箇所** - `_blocks()` L887: `t = _norm(el.get_text(" "))` — `get_text()` は href を読まん。`<a>` は `_ALWAYS_STRIP`/`_NOISE_STRIP` で消されとるのではなく、**単に破棄されとる** - `_render_list()` L901: `own = _norm(dup.get_text(" "))` — li 内も同じ - `_blocks()` L842 (見出し), L856 (table cell) も同じ **影響 (LLM にとってのマズさ)** 1. 出典 URL が素材として無い → citation hallucination（llms.txt 自身が「canonical HTML URL を cite せよ」と指引しとる矛盾） 2. **2段取得設計の急所が壊れる**: 1段目で次の fetch 先を決められない（「see the full update guide」だけ見て URL が確定できん）[1] 3. href 削除による token 削減は数百字オーダーで、見返りが小さい（5.4k字差の主な要因は HTML 由来ノイズ除去側） --- ### P2. anchor-only 残骸が本文に漏れる + 見出しに zero-width space - 原因: `_norm()` L80-85 は `\u00a0` と空白系しか掃除しん。`_NOISE_STRIP` L38 は `nav/header/footer/aside` の tag だけ（`<ul class=tablist>` や `<div class=breadcrumb>` は素通り） - 影響: token を食うだけや無く、モデルが「選択肢の一覧」誤認して回答に転載する --- ### P3. コードブロックが1語ずつ改行で分断される (最重要・P1より危険) **実測** [1] ``` docker run -d -p 3000:8080 --add-host=host.docker.internal:host-gateway ``` `pip install torch --index-url ...` も `pip / install / torch / --index-url` に割れる [1]。Markdown 版では1行で正しく残る。 - `_meta_block()` L1192 の `(受信上限で打ち切り)` と `_finalize()` L1091 の「本文長上限(MAX_STORE_CHARS)に達したため後続チャンクをキャッシュしていません」→ 実際には後続 chunk 取得可能（llms-full.txt 299.2k字 < 300k字 で `c46-c48` 取得成功）。bytes 側 truncated と max_store を混同しとる - L100-113 は末尾スラッシュを落とす。canon を送信 URL に流すと末尾スラッシュ必須の site で false 404（過去に確認済みの地雷） - 現状は原 URL 送信で正しく、404 メッセージも「末尾スラッシュ見直し / .md .txt 試せ」と正しく誘導しとる。ただし**明示コメントと回帰テストが無い** --- ## 2. 改善案 (FIX-A〜FIX-I, 優先度順) ### P0 — FIX-C: `pre` の連結仕様を独自実装に差し替え (低リスク・即効) `_blocks()` L847-851 を `_code_text(pre_el)` に置き換え: - span 間の separator は **`""`**（`get_text("\n")` をやめる）。テキストノードの改行だけで行を作る - `<br>` → `\n`、行番号 gutter（`data-line` / `.line-number` / `.astroid`）は除去 - インデントは `white-space` を壊さんとこだけ保持、tab は space 4 に正規化 - `_norm()` を経由させん（`_norm()` の ` ?\n ?` → `\n` 正規化が pre で余計な連結をする） - flag `[コード]` は現状維持 回帰テスト: `docker run -d -p 3000:8080 ...` が1行、`pip install open-webui` が1行、YAML が `services:` 形式で復元 --- ### P1 — FIX-A: href を Markdown 形式で復元（FIX-B と対で必須） 新規 `_links_to_md(container, base_url)` を `_extract_html()` の container 確定後・`_blocks()` 前に挿入: - `urljoin(base_url, href)` で絶対化（**送信 URL には使わん、表示専用**） - fragment および `utm_*` / `ref` / `source` は除去して normalize - 同一 host の内部リンクは `internal`、それ以外は `external` とフラグしてメタに出す - anchor text が URL と同一の自己リンクは bare URL に畳む - 画像のみリンク（`<a><img></a>`）は alt 由来の残骸にせんと `[図]` に寄せる **方式の分岐（要決定）** - A1 `inline`: `[text](abs_url)` — 引用の追従が容易、token +10〜25% - A2 `footnote`: 本文は anchor text のみ + chunk 末尾に `[n]: abs_url` 定義集 — token 効率が良く引用素材も確保。**2段設計と相性が高い（chunk 単位でリンクが完結する）** - Valve 追加: `KEEP_LINKS: bool = True`, `LINK_STYLE: "inline"|"footnote"|"off"`, `LINKS_MAX_PER_CHUNK: int = 40` **注意**: FIX-B 無しで FIX-A だけ入れると nav/sidebar/breadcrumb のリンクまで復元して本文が汚れる。必ず対にする。 --- ### P1 — FIX-B: anchor-only 残骸とリンクノイズを消す - `_NOISE_STRIP` を tag 基準から **セレクタ集合** に拡張: `nav, header, footer, aside, [role=navigation], [role=banner], [role=contentinfo], .sidebar, .menu, .toc, .table-of-contents, .breadcrumb, .tabs, [aria-label*=nav], .tablist`（現状の L395「コンテナ祖先は decompose せん」安全策は維持） - **2段構え**: href 付きリンクは残す（FIX-A）／href 無しアンカーテキストのみの block は捨てる（`el.find("a", href=True)` が無ければ drop） - `_norm()` L80 に制御/不可視文字除去を追加: `\u200b \u200c \u200d \ufeff \u00ad` + permalink anchor（末尾の `#`/`¶`/`​`）除去。前に潰した「looks_text の ctrl 文字判定」とは別物なので基準を分ける - 期待値: `c1` の nav ラベル列が 0 行 [1]、OUTLINE 見出しの U+200B が消える [1] --- ### P2 — FIX-D: ヘッダ/NOTES を正直に（LLM の誤判断防止） - 「ノイズ除去」を経路別表示に: `除去: 2,554字 (HTML解析)` / `変換なし (Markdown/テキスト経路: リンク保持)` - L1091 の文言を実測値ベースに差し替え: `本文 X/Y字・chunk m/n をキャッシュ済み（残り Z字は chunk で取得可能）`。**取れるのに「していません」と出す現挙動を禁止** - `_meta_block()` L1180 に `cached: c1-cN / 全M` を追加（bytes truncation と MAX_STORE_CHARS を別表示） - 404 メッセージは現状で良（綴り・階層・末尾スラッシュ・llms.txt/sitemap/.md/.txt 誘導）。P8 の候補 URL と接続する --- ### P2 — FIX-E/F/G: OUTLINE と query の usability（巨大 corpus） - FIX-E: `_outline(max_rows)` を **`OUTLINE_ROWS: int = 45` Valve 化**（0=無制限、mode="outline" 時は既定無制限）。省略時に「この site は .md / .txt / llms.txt が有効な可能性」の1行を NOTES に出す - FIX-F: 分割 group の outline 表示を `## Pages (31 chunks: c2-c32)` の1行に畳むか、各分割 chunk に**最初のリンク先/最初の語**を添えて判別可能にする。`_flag_note()` L1134 側で対応 - FIX-G: query 打ち切り時に「未表示 hit N件は chunk=cX,cY,cZ にある」の **chunk ID 列を必ず出力**（hit の chunk 対応は保持済み）。Valve `QUERY_MAX_WINDOWS: int = 14` --- ### P3 — FIX-H: Markdown 版の自動探知（案内のみ、自動 fetch はせんとく） 1段目の HTML 応答で候補 URL だけを NOTES に列挙: - `<link rel="alternate" type="text/markdown">` があれば最優先 - 決定的パターン: `<page>/` → `<page>.md`, `<page>.txt`（docs 系）、`github.com/<o>/<r>/blob/<branch>/<f>` → `raw.githubusercontent.com/<o>/<r>/<branch>/<f>` - site 直下の `llms.txt` 有無（known host list or 1回だけ HEAD） **自動 fetch を入れん理由**: hop 数が増えると SSRF 検査と redirect 追従コストが増える。モデルに選ばせる方が事故りにくい。併記注記: 「取得は .md で良いが、引用には canonical HTML URL を使え」 --- ### P3 — FIX-I: 不文律の明示と回帰テスト - `_canonical()` docstring に「**cache key専用。送信URLには使うこと**（末尾スラッシュ必須 site で false 404 になる）」を追記 - 回帰テスト追加: 末尾スラッシュ必須 page で `quick-start` と `quick-start/` が同じ cache entry を指し、かつ送信は原 URL で 200 --- ## 3. 検証計画 (前回の検証資産を流用) -
